Criterio general

  • ISIS seguirá siendo el sistema base.
  • GestionCyE será un sistema web complementario.
  • Tomará información de la API de ISIS y generará información propia.
  • Producción se ejecutará en un VPS existente.
  • El detalle de entidades y campos se define en el trabajo “Datos”.

Separación: “Datos” evalúa endpoints, campos, relaciones, volúmenes, tiempos y reglas funcionales. “Arquitectura” elige tecnologías y componentes usando esos resultados.

Acceso a la API de ISIS

  • Existe una API key funcional con acceso a datos reales.
  • La API puede consumirse desde diferentes computadoras y redes.
  • Actualmente varios Excel obtienen información desde la API.
  • La exploración inicial puede hacerse localmente, sin esperar el despliegue en el VPS.

Actualización requerida

  • Se conservarán al menos los últimos tres años de información.
  • Primero habrá una carga histórica.
  • Después habrá sincronizaciones incrementales continuas.
  • Lo creado en ISIS deberá aparecer en GestionCyE en menos de un minuto.

Condición de funcionamiento

Las consultas serán pequeñas y se ejecutarán en segundo plano. Las pantallas trabajarán sobre datos locales para no quedar esperando a ISIS.

ISIS permite modificar, anular y eliminar registros, pero no ofrece una fecha de modificación utilizable.

  • Descargar automáticamente registros nuevos.
  • Releer automáticamente el conjunto operativo activo.
  • Permitir que el usuario actualice un registro puntual.
  • No releer periódicamente todo el histórico.

Un registro histórico modificado o eliminado puede quedar desactualizado hasta su actualización puntual. Se mostrará su fecha de última sincronización.

“Activo”, “pendiente” o “cerrado” podrá ser un estado calculado por GestionCyE; no se asume que ISIS lo entregue resuelto.

VPS compartido

El servidor alojará GestionCyE y otros programas. Hay dos programas adicionales previstos y el objetivo posible es llegar a cuatro en total. Todavía no fueron desplegados.

  • Los otros programas tendrán poca carga.
  • Patín funcionará principalmente fuera del horario de GestionCyE.
  • El taller de reparaciones tendrá menos de 1.000 trabajos anuales.

Implicancia: cada programa deberá quedar separado en dominios, configuraciones, procesos, credenciales, datos y backups.

Decisión: utilizar Docker en desarrollo y producción para aislar los programas y mantener entornos consistentes.

Se monitorearán CPU, memoria y disco. Si no alcanza, se ampliará el plan del VPS.

Observaciones importantes

La aplicación no deberá operar normalmente como root.

El backup semanal existe, pero todavía no sabemos qué cubre, cuánto conserva ni si su restauración fue probada.

Próximas decisiones

  1. Relevar servicios instalados y activos en el VPS.
  2. Elegir backend, servidor web y base de datos.
  3. Definir cómo se almacenará y sincronizará la información de ISIS.
  4. Definir seguridad, secretos, despliegue, monitoreo y recuperación.
